Gossipsub 1.4

Large-message handling for libp2p's gossip protocol: a specification and a working prototype.

View the code ↗

runs locallyPythongithub.com/codealisha99/Gossipsub

What it is

Gossipsub is optimised for small messages, but decentralised systems increasingly need to move 5–100 MB payloads such as model updates and state snapshots. Gossipsub 1.4 adds a segmentation layer on top of the existing mesh.

This repository holds an RFC-style specification and a Python prototype, submitted for C4GT's DMP 2026. It stays backward-compatible with Gossipsub 1.1 peers.

How it works

  1. Segment: the publisher splits a large message into fixed-size chunks (64 KB by default).
  2. Envelope: each chunk travels in a GossipSegment with a shared message ID and a per-chunk SHA-256 checksum.
  3. Propagate: segments move independently through the mesh, tolerating reordering and partial loss.
  4. Reassemble: receivers buffer, verify and reassemble before delivery, so there's no head-of-line blocking.
